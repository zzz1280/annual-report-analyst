# 测评报告：首轮真实数据评测（贵州茅台 2023 年报）

- 日期：2026-10-24
- 语料：贵州茅台（600519）2023 年年度报告，143 页文本型 PDF（巨潮资讯网公开下载）
- 规模：694 → 700 分块（含报表归属修复后的表格分块），检索采用**纯稀疏模式**（字符 bigram + idf 加权，零 API 成本）
- 评测方式：**agent-in-the-loop**——LLM 环节（读数、出题、作答）由强模型 agent 模拟，
  解析/分块/检索/指标计算/引用审计等 Python 环节全部为仓库内真实代码原样执行；
  评分裁判为 3 个独立上下文的子代理（各评 7-8 题，互不知晓系统实现）。

## 总结果

| 指标 | 结果 | 说明 |
| --- | --- | --- |
| 财务指标计算正确性 | **4/4 与年报披露一致** | 营收 +19.01%、归母 +19.16%、扣非 +19.05%、经营现金流 +81.46%，本地计算与年报口径完全对上 |
| 报告引用审计 | 15 处引用，**0 处无效** | 机械校验 (p.N) 页码合法性 |
| 检索命中 hit@8 | **22/22 (100%)** | 22 题证据页全部落入 k=8 检索窗口；命中名次：rank1×17、rank2×4、rank4×1 |
| 引用有效率 grounding | **22/22 (100%)** | 回答中引用页 ⊆ 检索证据页（规则判定） |
| 回答正确率（LLM-as-judge） | **22/22 得 2 分** | 3 个独立子代理按 0/1/2 评分 |

## 分环节记录

1. **解析与分块**：pdfplumber 15 秒解析 143 页；"主要会计数据"（p.5）分块完整保留全部核心数字。
2. **读数与指标计算**：LLM 从"主要会计数据"表读出 6 个科目（本期/上期，取调整后口径），
   `compute_metrics` 纯 Python 计算的 4 个同比全部与年报披露数字一致——
   "LLM 只读数、本地算指标"的设计经真实数据验证。
3. **风险抽取**：修复定位逻辑后准确锁定 p.21 风险章节，抽出 4 条风险（宏观经济/安全/舆情/环境保护）。
4. **报告生成**：三个章节、15 处页码引用，审计 0 无效；含口径辨析（营业总收入 vs 营业收入）与估算标注（资产负债率估算口径及偏差方向）。
5. **QA 评测**：22 题（数字题/事实题/口径辨析题，横跨重要提示、经营分析、ESG、关联交易、四大报表附注），
   流程为 检索→仅依据检索材料作答→独立裁判评分。

## 发现并修复的问题（跑真实数据才暴露的）

| # | 问题 | 现象 | 根因 | 修复 |
| --- | --- | --- | --- | --- |
| 1 | 标题误判 | 大量单行碎块 | 正则把"一、本公司董事会……"等长句编号项当章节标题 | 标题必须 ≤30 字短行 |
| 2 | 页眉杂讯 | 关键词命中率被稀释 | "2023年年度报告""√适用"等每页重复 | 自动识别"出现在 ≥30% 页面的短行"并剔除 |
| 3 | 词级匹配脆弱 | "研发投入"表进不了 top3；长查询被填充词稀释 | jieba 词面交集过于刚性 | 换字符 bigram + idf 加权（BM25-lite），并移除 jieba 依赖 |
| 4 | 风险页过匹配 | 正文顺带提"风险管理"的页全被收集 | 纯全文关键词定位 | 优先以"风险"为标题出现的页，退而求其次才全文匹配 |
| 5 | 表格丢失归属 | "母公司资产总计"检索 MISS（首轮 21/22） | 表格分块不知道自己属于哪张报表，无法与合并口径区分 | 四大报表标题识别为章节边界，表格分块加 `[母公司资产负债表]` 式上下文前缀 |
| 6 | 报告数字抄写错误 | 真实 LLM 把 74,734,071,550.75 抄成 747,340,71550.75（千分位错位），引用审计查不出 | LLM 逐位复制长数字易错位 | 新增 `audit_numbers` 数字审计（千分位合法性 + 全量数字溯源），并在提示词中要求金额用亿元两位小数 |
| 7 | 引用格式漂移 | 模型输出 `(p.第2-2页)` 导致引用页解析失败 | 格式约束不严 | 问答 SYSTEM 明确"格式严格形如 (p.5)" |
| 8 | 提示词迭代回退 | 第二轮收紧问答提示词后满分率 86.4%→77.3%，出现 2 个"引用对但选数错" | 新增"逐字符复制+完整列出"指令诱发模型抓取相邻行数字 | 回退至第一轮提示词；n=22 下单轮对比噪声大，提示词改动须以评测回归为准 |

每次修复前后都有可复现的对比（如 #5：修复前 hit@8=21/22，修复后 22/22）。

## 真实 LLM 复测（glm-4.6 + embedding-3，2026-10-24）

配置真实 API key 后全链路复跑（混合检索：embedding-3 语义向量 + bigram/idf 关键词）：

| 指标 | agent 模拟（首轮） | 真实 LLM 第 1 轮 | 真实 LLM 第 2 轮（提示词收紧，已回退） |
| --- | --- | --- | --- |
| 引用有效率 grounding | 100% | **100%** | 100% |
| 满分率（judge=2） | 100%（oracle） | **86.4%** | 77.3% |
| 无错误回答（judge≥1） | 100% | **100%** | 90.9% |
| 证据块命中 hit@8 | 22/22 | 同索引复用 | 同索引复用 |

关键发现：

1. **LLM 读数环节零误差**：`extract_figures` 抽取的 6 个科目逐位正确，`compute_metrics` 输出与年报披露完全一致——结构化抽取 + 本地计算的分工在真实模型下依然成立；
2. **报告环节出现数字幻觉**（问题 #6）：催生了数字审计功能，报告重新生成后 24 个数字全部可溯源、千分位异常 0；重新生成后引用 33 处、无效 0；
3. **grounding 抓不住"选数错误"**：第 2 轮两个错误答案引用页完全合法，但数值取自证据块的相邻行——裁判层（LLM-as-judge）是必要防线；
4. **提示词改动非单调**：为治"完整度失分"而收紧的指令反而诱发选数错误，已回退。教训：每次改动必须跑评测回归，单轮 n=22 的差异要结合具体失分案例判读。

消耗量级：全程（建索引 embedding + analyze×2 + 评测×2）约 120 万 token，约占 3 亿额度的 0.4%。

复测指引：资源包恢复后，`.env` 换回 `LLM_MODEL=glm-4.6`，对 5 份年报重跑 `parse`（重建混合索引），
再对同一批 `data/eval/qa_*.jsonl` 运行 `run_eval` 即可对比。

### r4 实验系列：RRF 融合、查询前缀与口径加权（负结果，已回退）

在 r3 配置上依次尝试三项检索改动，均以评测判定淘汰，全过程如实记录：

1. **RRF 倒数排名融合 + 无条件口径加权**：灾难性回退（万科 18/19 拒答）。根因：RRF 把相关度
   幅度压缩一个量级，±0.15 的口径加权相对过大，几百个"合并"标签块被一律加分，四大报表的
   通用表头块霸占了所有查询的 top-4。恢复加权求和后精准度回归（"武汉公园5号地块合同金额"
   直接命中含 3,510,015,902.19 的明细行）；
2. **bge 查询指令前缀**（官方推荐做法）：实测满分率 76.4%（-3.8pp），r3 已修复的三题拒答回退
   ——前缀改变了所有查询向量。已默认关闭（机制保留，向 QUERY_INSTRUCTIONS 登记即启用）；
3. **显式口径加权**（仅查询含"母公司/合并/本行"时 ±0.15）：77.4%，与 r3 的差异在运行噪声内，
   无可测收益。默认关闭（LLM_SCOPE_ADJUST 可启用，机制与单测保留）。

**最终发布配置 = r3**：本地 bge 语义 + bigram/idf 关键词（原始余弦 0.7/0.3 加权）+ 两道自愈
防线，106 题 80.2% 满分率、100% 引用有效率。本轮实验的产出是两条工程教训：
**排名融合不能丢掉相关度的幅度信息；任何"官方推荐"的技巧都必须先过本语料评测再采用。**

## 效度限制（诚实声明）

- **首轮生成环节是 oracle 模拟**：检索命中即由强模型作答。上节的真实 LLM 复测已补上这一缺口；
  后续大改 prompt 后仍应以 `run_eval.py` 复测为准。
- **单语料**：仅 1 份年报 22 题，尚不足以支撑统计结论；建议扩到 5 份年报 × 100 题。
- **纯稀疏检索**：未测混合检索路径；命中名次分布（4 题在 rank2-4）说明语义向量仍能改善排序。
- **裁判独立性有限**：裁判为同家族模型的新上下文子代理，且 answer 与 reference 出自同一模拟器。
